Defines the fixed set of tags for SecretCsv's sample tag file — a plain file kept in this repo's `SampleData\` folder, **not bundled in the installer or the MSIX package, and never auto-imported** (README.md §11). It's here so anyone can point Import's two file pickers at `construction.md` and `construction.csv` and see the whole flow work without owning real data of their own yet. Its `##` line, **Construction**, specifies the entity name, which is also its record-store filename (`Construction.txt`) once imported. A CSV file is importable only if its header row contains one column per tag below, matched by name (case-insensitive, any column order) — extra or missing columns block the import and are named explicitly in the Status flyout, not silently skipped (README.md §9). The first tag listed plays the "Category" role (top-level grouping, and the field exploded into multiple records when semicolon-delimited on import); the second tag listed plays the "Nickname" role (searchable business identifier).

There is no folder picker and no folder-as-project model (README.md §3) — Import uses two independent file pickers instead. At Import time, whichever tag file was picked (this one or any other) is copied into AppData as `<EntityName>.md`, alongside the `<EntityName>.txt` it produces (README.md §5). This file itself is never modified by the running app; only the copy in AppData is touched.
